# Contributing to Popper

Popper aims to make research actions verifiable across domains. Contributions should preserve the boundary between agent suggestions, execution facts, independent evaluation, and scientific conclusions. Read [VISION.md](VISION.md), [ARCHITECTURE.md](ARCHITECTURE.md), and [ROADMAP.md](ROADMAP.md) before changing that boundary.

## Local setup

Use Python 3.10+ and Node.js 20+. In a fresh checkout:

```powershell
python scripts/dev_setup.py --test
```

The script installs Popper editable, runs `npm ci`, builds the Vite workbench, stages its assets and the two offline demos, then runs focused smoke tests. Use `--extras workstation,ml` on Windows if you need the real ConPTY terminal and the Wisconsin classification example. It does not install or start a model service. If you only want to check that committed package assets match their sources, run `python scripts/dev_setup.py --check`.

For a safe first run, create a new directory and use the offline ODE example:

```powershell
popper demo init .\my-ode --case ode-convergence
popper research init .\my-ode .\my-ode-run
popper research run .\my-ode-run --trusted-local
popper research status .\my-ode-run
```

`--trusted-local` executes code from that project with your account's permissions. Only use it for code you trust. Generated code belongs in a supported sandbox worker; do not silently fall back to trusted-local execution.

## Changes and verification

- Keep the existing research objects, event histories, budget accounting and frozen-input hashes backward compatible. If a migration is needed, make it explicit and auditable rather than rewriting old identities.
- Add a failure-path test for changes to persistence, confirmation, execution, or evidence verification. Include a real end-to-end case when an integration claim cannot be proved by a unit fixture.
- Run `python -m pytest -q --tb=short` for Python changes and `npm run build --prefix frontend` for frontend changes. The optional-dependency and sandbox CI jobs cover additional platform paths.
- If you change `frontend/`, run `python scripts/stage_frontend.py`. If you change either built-in offline example, run `python scripts/stage_demos.py`. CI rejects drift between source and staged assets.
- Do not commit credentials, local `.env` files, mutable run databases, holdout labels, or generated build directories. Report any suspected exposure privately to maintainers before opening a public issue.
- Run `python .github/scripts/check_tracked_secrets.py` before sharing changes. CI checks common credential patterns and sensitive filenames, but this narrow gate is not a comprehensive secret audit; inspect your own diff as well.

The [core identity and API RFC](docs/rfcs/0001-core-identity-and-api-v1.md) documents entity IDs and write semantics. Small, reviewable changes with reproducible tests are easiest to merge. A license decision is pending; until a LICENSE file is added, do not assume the repository grants open-source redistribution rights.

## Experimental external domain packs

An installed package can provide a module-level `DomainPack` singleton without editing Popper's built-in registry:

```toml
[project.entry-points."popper.domain_packs"]
my-domain = "my_package.domain:PACK"
```

Set `POPPER_DOMAIN_PACKS=my-domain` in every process that initializes, runs, or replays that domain. Multiple names are comma-separated. Popper loads only explicitly selected names, rejects missing or ambiguous entry points and duplicate evaluator IDs, and binds the pack's `evaluator_entry()`, implementing class module SHA-256, and its installed distribution payload SHA-256 to the experiment's saved evaluator hash. The payload digest covers recorded files outside installer metadata and generated bytecode; an edited helper module in that distribution invalidates replay. Distributions without an enumerable file manifest are rejected. This does **not** hash transitive dependencies or unrecorded files: pin external package and dependency versions when sharing a reproduction bundle; they are not embedded in it.

This interface is experimental, not yet the stable plugin SDK described in the roadmap. Loading an entry point executes third-party Python with the current process's permissions. Only install and select audited packs you trust; this selection is not a sandbox or a signature check.
The [separately packaged example](examples/external-order-pack/README.md) is a starting point. CI builds and installs its wheel alongside an independently built Popper wheel, then completes and replays a non-ML experiment without editing Popper's built-in domain list.
