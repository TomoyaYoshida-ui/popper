# 工作区开源项目复用评估

更新：2026-09-08

这些目录是 Popper 的开源组件源。接入状态以 `integrations/vendors.json` 和可执行适配器为准；未登记的目录仍只是候选来源。当前压缩包目录没有 Git 元数据，因此用许可证、入口和 SKILL 文件的 SHA-256 固定实际版本。

## scientific-agent-skills-main

- `skills/arbor/scripts/tree.py` 已通过 `arbor-tree-v1` 接入，节点、frontier、证据、洞见传播、剪枝、cycle 和 merge 状态可由 Popper 结构化读取与修改。
- Arbor 的 worktree 用于隔离候选代码版本，不提供恶意代码安全边界。
- 其 held-out merge gate 若在多轮搜索中反复暴露同一 test 结果，会形成自适应反馈。Popper 当前采用“冻结后一次最终确认”；后续借入树结构时保留该限制。
- Arbor 保留供应方状态文件，Popper 负责路径限制、指纹验证、跨组件来源和最终测试约束；它不替换 Popper 当前实验状态机。

## ResearchStudio-main

- ResearchStudio-Idea 的真实 `run.py next` 已通过 `idea-next-v1` 接入，原始导航文本被解析为结构化状态。
- `idea-to-arbor-v1` 已能选择最终修订、coherence 修订或初始生成候选，把 `title + falsification_prediction` 写入 Arbor，并记录候选文件 SHA-256。
- `paper_search` 已通过 `paper-search-v1` 接入（结构化分来源回执 + 去重排序），`scoop_check` 已通过 `scoop-run-v1` 接入；两者都在非沙箱路径执行供应方代码，需显式 `--trusted-local`。完整 Idea Spark 仍需要 LLM 子任务和检索连接器，不能把导航器接通等同于整套流程无人值守。

## nature-skills-main

- `nature-ref-verifier` 当前主要是 SKILL、agents 和 references 结构。接入前需要确认其中是否存在可复用脚本/API，不能按服务接口估算工期。
- 写作、图表和传播不在当前发布门内。

## AI-Research-SKILLs-main

- 可作为具体框架、训练方法、论文写作的操作参考。
- 技能数量不代表可直接集成的功能比例。只在真实任务提出明确需求时选用对应模块。

## academic-research-skills-main

- 可借鉴引用门禁、审稿协议和 held-out 评测思路。
- CC-BY-NC 或其他限制需按实际文件确认。商业产品不能以“重写”一句话代替法律与来源审查。

## research-agent-v2/skills

- 这是前期整合设计，提供流程命名、模板与来源映射；目录与 skill 名已统一为 `popper-*`（原 `ferrata-*` 是退役名）。
- `popper-shared/schema` 和 `scripts` 中仍有规划性 README；没有脚本的能力不能计入已完成比例。现状已在 `skills/README.md`「实现状态」中如实标注：本目录是设计规格，不被 `popper/**` 或测试消费，除 `validate_results.py` 外脚本尚未实现。
- 后续保留有真实消费方的契约，删除或降级只描述愿景、没有可执行入口的重复 skill。
