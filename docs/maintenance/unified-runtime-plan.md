# 统一研究运行时改造

实施对象：本机原仓库 `C:\Users\wangj\Desktop\research\research-agent-v2`。
本轮不发送真实模型请求，不推送远端，不重写旧实验及其失败结果。

## 根因与边界

此前迁移评测同时维护模型动作模式、JSON 检查点、候选选择和确认执行。
这些规则与原 ResearchController/ResearchStore 不同，形成第二套状态权威。
停止动作又绑定候选 ID 和最终判断，导致表达错误能够阻断已经有效的科学证据。
范围含义还由脚本推断，控制器固定使用 s1/s2；网络、JSON、语义层各自重试，
使一次逻辑决策可能发送四次请求，并重新开始总时限。

科研上的阴性或证据不足不是软件故障。运行时应分别保存规划状态、执行结果、
独立判断和未经验证的模型解释，保留失败分母，并让预登记规则决定确认资格。
代码不能保证模型永不出错；它应使错误有界、可定位、不会伪造科学支持。

## 实施顺序

1. 以 Pydantic v2 的动作专属类型生成提示 Schema 和解析规则，停止不带执行目标。
   模型解释使用独立主体、版本、范围与证据引用，没有分数和置信区间写权限。
2. 增加项目公开适配器，从冻结声明读取主范围、指标、单位、特征名和候选空间。
   缺失/矛盾范围在执行前拒绝；旧声明标明派生来源，不推断隐藏数据机制。
3. 公共运行时只通过原控制器执行，规划收据存入原 ResearchStore 事务命令和事件链。
   请求开始、响应、动作完成分别持久化；歧义请求不重发，已验证执行只补缺失收据。
   限额由控制器确定，达到实验上限不要求额外模型停止响应。
4. 抽取共用确认路径。旧阈值门禁保持；新初始化冻结的最佳开发指标策略可确认
   inconclusive 候选，但其科研判断仍由独立评估器计算。原确认保护与审批保留。
5. 网络重试、JSON 修正、语义纠正共享两次尝试、稳定逻辑身份和总截止时间。
   未知用量保留原保守预留，不能因纠正或重启释放为零。
6. 迁移评测仅负责策略对照与统一名单屏障，不直接执行、计分、写科学记录。
   新比较插件按注册 Schema 分派；用非 FIGS、非 MAE、非种子 17 的项目检验扩展边界。
7. 原 CLI、新协议工作台与 campaign 通过同一公共边界；旧项目继续兼容原功能。
   未支持的能力在预检阶段拒绝，不退回另一条执行路径。

## 验证与交付

针对历史停止字段冲突、非法模型事实、范围改名/置换、版本追加、模型失败保留证据、
请求两次封顶、中断恢复、确认一次消费和未知用量做离线测试。
冻结实现后分别运行 Windows 全量、WSL 非 root 原生 Linux、bubblewrap 沙箱及安装入口。
容器只验证构建与安装，不替代沙箱验证。未运行的检查明确保留为未验证。

按协议/运行时与入口/迁移适配分阶段本地提交。完整轨迹、数据库、数据和凭据留本地；
只提交代码、测试、脱敏摘要和复现配置。原有删除状态保持。

## 采用成熟项目的具体做法

- [Pydantic AI 输出机制](https://pydantic.dev/docs/ai/core-concepts/output/)：
  Schema 与验证由同一类型定义产生，校验错误有界反馈。采用其边界原则及 Pydantic，
  不叠加一个有默认隐藏重试的网络客户端。
- [LangGraph 持久执行](https://docs.langchain.com/oss/python/langgraph/durable-execution)：
  对有副作用的步骤保持幂等和明确收据；保留现有外层 campaign 图，科学事实仍由
  ResearchStore 和受保护的实验存储负责，不把图检查点当作科研结果。

这些框架处理软件协议与恢复，不能替代科研项目的独立单位、统计规则和制品验证。
