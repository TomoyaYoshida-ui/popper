# 独立迁移试点评测协议与恢复纪律

入口：`evaluation/run_transfer_pilot.py`；独立核验：`evaluation/verify_transfer_pilot.py`。
运行目录与原 FIGS 30 次账本分离，原记录不修改。

任务由 `evaluation/transfer_tasks.py` 准备。T01 固定官方 Wine Quality 红酒 CSV 摘要，
完全相同的输入行分组划分。T02 采用预先指定的生成机制和独立环境切片。
T03 采用独立噪声目标及零预测基线。生成机制和真相单独存在本地 oracle 文件，
不复制到单元项目，也不进入模型上下文。

每任务八个冻结模型配置、三种策略各三次，合计 27 单元。
每单元最多四个开发候选；T02 按独立环境开发 MAE 选最终候选。
所有候选名单和未经验证的最终模型判断统一冻结后才打开确认通道。
普通迭代与证据驱动策略读取相同原始指标、区间、范围及引用，
只有后者额外读取结构化判断及建议。普通迭代仅为内部消融。

真实调用共用新 SQLite 账本：最多 180 次请求、五百万保守 token；
模型单元各九次、二十五万 token；预检六次、十万 token。
额度包含重试与格式修正。凭据只读 `POPPER_API_KEY`。
该试点明确采用保守预留模式：缺失用量保留全额预算占用，
仅在剩余额度内允许后续新逻辑请求，不修改原有客户端的默认停止策略。
预检也受 Windows/Linux/真实 Linux 沙箱/Docker 门禁约束。

步骤先记录开始标记，再发请求或修订；完成后保存检查点。
模糊中断导致未完成步骤时停止单元，不重发或重复修订。
完整回执可以幂等恢复；失败单元进入分母，不能补跑到成功。
确认开始标记禁止重复消费；启动后失败保守占用成对执行预算。

`agent_assessment` 始终未经验证。独立科学判断引用原始评估制品，
重算 bootstrap、区间和预注册预测区域，不能由模型覆盖。
修订产生新假设与设计版本；已评估版本不被事后改写。

离线命令为三种策略统一使用固定队列的传输/执行夹具。
它能检验 27 单元闭环和确认保护，不能用来评价模型策略差异。
报告只展示单个冻结任务内的描述性差异；重复运行不算独立数据集，
不主张通用科研能力、统计优势或因果机制已成立。

局部验证：Windows 最新迁移/入口测试 9 项（其中门禁阻断测试单独通过）；
Linux 同组测试 9 passed。派生后台任务等待竞态另有确定性回归与真实 SSE 回归，
Windows 4 passed。完整 Windows/Linux 回归与 27 单元结果另行提交。

离线首轮审计：27 个开发单元均完成，18 个确认完成、9 个 T02 确认因缺少源环境切片失败。
这是执行/评估适配失败，不是科学反证；原回执保留，不重跑已消费的确认通道。
修复采用新增的可选预注册字段 `analysis_slice_splits=['dev']`，
在 T02 开发阶段评分两个环境，确认阶段只评分实际登记的完整独立环境。
空切片依旧被严格拒绝。既有字段缺省仍对 dev/test 都适用。
外部签名确认暂不支持这个新字段的局部阶段范围，明确拒绝注册，不默默忽略范围。

本试点的操作员会看到离线工程验证的确认结果；模型选择上下文始终只含开发证据。
数值阈值、候选空间、数据种子和比较规则均沿用用户预先指定值，
没有根据确认效果调参或挑任务。报告不能宣称操作员盲法或全新科学发现。
