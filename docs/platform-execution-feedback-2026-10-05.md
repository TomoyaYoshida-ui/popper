## 运行时基础模块：未启用

`popper/harness/runtime.py` 与 `opencode_runtime.py` 提供经官方 v1.17.9 协议核对的 loopback HTTP/SSE 适配。认证、目录和会话绑定、未知投递拒绝重发、取消请求及断流核对已有测试。原生事件接口不提供历史重放，游标仅用于去重。进程内记录不能替代宿主重启后的持久发送意图。

`popper/model_gateway.py` 提供独立持久模型请求回执：预算回调、不可变脱敏快照与实际请求一致、已知用量结算、取消终态与结算分离、未知发送/用量项目级阻断，以及宿主密钥保护。当前只支持流式 Chat Completions，拒绝非流式及其他协议，不提供自动直连回退。

下一批正式桥接必须同时具备以下条件，不能直接把适配器设为默认 Harness：

1. 宿主持久化 native session/message 发送意图与绑定；重启、掉线时只读核对，不重发不明请求。
2. 独立配置及精简环境，拒绝继承全局认证、项目插件、未授权 provider 或原生文件/Shell/子 Agent 权限；仅开放受控 Popper 工具桥。
3. 所有标题、小模型、摘要、压缩和辅助调用都经过唯一网关、同一真实账本，配置及实际 wire 请求经模拟验收；不得自动切换 provider 绕过拒绝。
4. 工作台使用真正的 runtime 事件，同时继续由现有科研服务、持久 Job 与明确对象决定研究终态和确认资格。
