## 0. 产品目标与首版切口

远期目标仍是帮助研究者形成有价值的研究问题、完成实验并形成可靠论文。首版从已有可运行项目切入：用户提供代码、研究假设、数据划分、评估协议和预算；Agent 复跑基线、提出候选、按开发集反馈推进实验，冻结候选后执行最终确认，输出证据支持的结论与下一步建议。

不把录用率、重大创新、查新穷尽性、固定节省时间当成机械保证。产品价值假设是：在固定预算内，减少研究者完成可靠实验判断所需的时间。

### 0.1 范围分层

- **当前 M0 工程切片**：Python 本地执行；显式 experiment.json 项目适配；控制器确定性评分（域包注册表见 §3.2）；预注册配置候选；可选 BYOK 模型根据开发集指标选择下一候选；冻结、一次性最终测试、claim、事件日志、离线重算与本地工作台。
- **真实公开数据接入**：Breast Cancer Wisconsin (Diagnostic) 的 569 个样本、30 个数值特征和二分类标签，比较 GaussianNB、逻辑回归、随机森林、RBF SVC 与 Extra Trees。该接入验证真实 ML 工程链路，不作为医学有效性或科研创新证明。
- **论文 claim 复现**：Street et al. (1993) 的三特征、单分离平面、10 折 accuracy 97% claim 已完成方法近似复现。协议、UCI 原始数据 hash、逐折预测、结果和离线核验器保存在 `reproductions/street-1993-wdbc`。算法完全一致性因原 MSM-T 软件、参数和 fold 分配不可得而明确降级。
- **首个真实研究试点**：选择一个用户已有、可运行、可承担算力费用的 ML 项目；实现对应评估适配器；加入基于文献的候选依据和少量受控代码修改。不能拿合成二次回归代替真实科研有效性验证。
- **随后扩展**：容器隔离（仅 BYOK 云算力 / 第三方仓库复现场景启用，本地路径已由 OS 原生沙箱覆盖，见 §2.2）、GPU 运行环境、有限领域反证查新、历史日志导入、代码候选树、实验包导出。
- **暂缓**：从任意研究方向全自动选题、任意仓库自动理解、全自动论文写作/投稿、海报视频、社区语料共享、铺开多学科覆盖。注意区分：多领域的**接入抽象**已落地（§3.2 的域包与两种任务形状），三个试点领域（收敛阶 / 算法吞吐 / 处理效应）已各自接入并暴露过不同缺口，但它们都跑在带真值的合成或公开队列上；真实领域广度仍未验证，见 §9.4 的待验证清单——抽象可用不等于领域广度已验证。

### 0.2 成功与失败的输出

用户看到具体变化、基线与候选结果、证据来源、适用条件和未解决问题。必须区分：

- `supports_threshold`：在指定评估范围内达到预注册描述性改善阈值。
- `insufficient_evidence`：当前结果不足以支持阈值；不自动解释为假设被证伪。
- `execution_failed / interrupted`：工程执行未完成，不能转化为科学负结果。
- 后续统计适配器可增加 `supports / does_not_support`，但必须附实验单位、功效和不确定性说明。

不以 claim 绑定率代替稿件就绪度，不以 novelty 分数代替研究者判断。消融可提供机制证据，但不自动证明因果机制。

## 1. 保证边界

### 1.1 五类事实分离

1. **存在性**：证据文件或引用记录存在。
2. **一致性**：结论数字、方向与绑定证据一致。
3. **正确性**：评估实现、数据使用和研究设计有效，需要额外检查。
4. **复现性**：按明确环境与协议重跑或重算，分级验收。
5. **创新性**：与已有工作比较后的研究判断，不由机械门禁承诺。

`results.json` 是正式结果接口，不是可信性的原点。候选程序只能交付预测，由控制器评估；控制器掌握指标定义、评分逻辑和最终数据标签。恶意候选的权限隔离必须由系统权限/OS 原生沙箱实现（本地路径无容器，见 §2.1/§2.2），不能由提示词或 JSON 格式保证。

### 1.2 证据可信状态

后续历史数据摄入采用 `imported_unverified / user_attested / controller_scored / independently_reproduced` 等显式状态。用户确认历史指标映射，不等于验证实验正确。当前 M0 正式结果标记为 `controller_scored_trusted_local`，仅表示可信本地执行后的控制器计分。

### 1.3 三种复现

- **离线证据重算（当前已实现）**：校验输入与产物 hash、事件链，从逐样本预测重算指标和 claim；不调用模型，不执行候选代码。
- **同环境实验复跑**：重新执行候选，比较预注册容差；M0 的多种子运行不代替专门的独立复现验收。
- **跨环境复现**：另设平台与容差协议，不承诺 bit-for-bit。

当前事件链用于发现意外修改；没有外部签名锚点，不能称作不可篡改。原始模型提案请求与响应保存用于审计，但当前没有实现整个 Agent 决策流程的全事件重建。

## 2. 核心架构

依赖流：本地工作台 / CLI → 实验状态机 → 候选提案 → 本地执行副本 → 控制器评分 → 结果与证据 → claim / 报告。

### 2.1 当前实现

- Python 3.10+ 标准库，零运行时第三方依赖。
- SQLite 保存协议、运行状态、事件链和结果投影；事务保护预算预留、运行占用与最终测试消费。
- 每次运行复制显式注册的 Python 源文件，使用独立工作目录。执行边界按 **OS 原生沙箱策略**设计（对齐 Codex/Trae 的本地模式，不引入容器）：文件写作用域限定实验工作区、根目录与受保护目录只读、网络默认阻断、越界操作回退人工审批。当前已落地进程级约束、**Windows 低完整性文件写作用域**（候选进程降级到 Low IL，仅运行工作区可写，既有的输入/代码副本与项目其他目录只读）、**低权限进程**（Low IL 后令牌被锁无法再调整特权，并尽力剥离危险特权）、**尽力而为的 HTTP 代理拦截**（代理指向死端口，拦截遵循代理的 HTTP(S) 客户端）、**Python 层命令拦截**（sitecustomize 注入，高危命令直接拒绝；可用原生 API 绕过，非内核级）、**Job Object 资源限额**（内存/CPU 时间/进程数，内核强制，实证有效）与**管理员门控的内核级断网**（提权时经 WFP/netsh 对专用 python 副本做程序级出站阻断；非提权环境不可用，仅代理拦截）、**保留集内核级禁读**（候选运行窗口内给已注册的测试数据集加 Windows 强制完整性 `NO_READ_UP` 标签，降级到 Low IL 的候选读它在内核层被拒 EACCES，窗口结束即恢复；边界见下条）。除该保留集禁读外读取不受限，裸 socket/DNS 在非提权下不受限，工作目录仍不是完整操作系统安全边界。
- 子进程参数仅传入训练集、待预测特征、配置、种子和输出路径，最终标签由计分器读取；`--sandbox` 消费测试集（`split=test`）时，上述内核禁读把已注册的测试数据集对候选进程封住——这是权限隔离，不是接口级隐藏。如实标注边界：该保护只覆盖注册的测试数据集文件本身（同账户下候选仍可读其它 Medium 文件），且只在 Windows 强制完整性标签可用时成立；不可用时 `--sandbox` 对测试划分与 `confirm` 直接报错（且发生在 `test_consumed` 提交之前，不白丢测试访问），不静默降级为「候选可读」。需要账户级/主机级隔离的正式确认仍应使用外部评估服务。
- 每个种子在独立进程组/作业对象下执行；超时或失败时终止整棵进程树（含候选再 fork 出的子进程），避免失控子进程残留。可选 `mem_limit_mb` 在 POSIX 下经 `RLIMIT_AS` 限制子进程地址空间、`cpu_time_seconds` 经 `RLIMIT_CPU` 限制 CPU 时间。这是"进程级防失控"，与上条所列已落地项共同构成沙箱策略的当前子集；非提权下的裸 socket/DNS 与账户级隔离仍属后续项。
- 本地 HTTP 工作台只绑定 127.0.0.1；会话 token、Host 校验、同源检查保护控制接口；不提供任意路径读取或 shell 接口。
- BYOK 是可选提案适配器：OpenAI-compatible chat/completions 接口，模型只能从预注册配置中选下一候选并给出假设；请求仅包含目标、候选和开发集摘要，不包含测试反馈。默认是明确标注的配置队列，不伪装成 LLM。
- 编码 Agent 走 **harness** 接入（`popper/harness/`，注册表 + `Harness` 协议）：Agent 只提交待写入的编辑与理由，落盘（`RevisionStore.create`）、预算预留与执行覆盖评估仍由内核独占——换一个编码 Agent 不扩大可信边界，也不能自报结果。接入优先用官方 SDK / 结构化协议（当前注册 `json_agent`：JSON 契约 + 一次有界纠错），不解析 Agent 的 stdout。新增一种接入 = 实现 `Harness` 的 1 个文件 + 注册表 1 行；`--harness` 供 `research implement` / `research run --autonomous-code` 显式选择，自带 `propose_revision` 的策略被适配成其中一种，控制器不再直连提案者。

### 2.2 后续架构演进

- 先统一 adapter 契约，再实施 **OS 原生沙箱策略**（本地执行不引入容器，对齐 Codex/Trae 模式）：
  1. **文件作用域**：仅实验工作区可写，根目录与受保护目录只读。Windows 用受限令牌/低完整性进程 + 目录 ACL，macOS 用 seatbelt，Linux 用 bubblewrap。后端由 `popper/sandbox` 的 `SandboxBackend` 协议描述、注册表登记；已登记 Windows 低完整性（`win_lowil`）与 Linux bubblewrap（`linux_bwrap`），seatbelt 尚未实现（故未注册，见下条）。
  2. **网络默认阻断**：无豁免则不可联网；需要联网的候选显式登记豁免。
  3. **命令拦截**：高危命令（`rm -rf`、`curl | sh` 等）直接拒绝，其余走白名单。
  4. **越界审批**：沙箱内无法完成的操作回退用户三选一（跳过 / 在沙箱外执行一次 / 加入白名单），与 code-proposal 的 `review_required` / `--approved` 审批流共用。
  git worktree 仍管理候选版本。容器仅保留给未来 BYOK 云算力或第三方仓库复现（B2.5）场景，不是本地执行路径的组成部分。
- **本地路径威胁模型（如实）**：单用户、仅运行用户明确可信的代码（`--trusted-local` / `--sandbox` 门禁，默认拒绝）；OS 原生沙箱覆盖写作用域、保留集标签读隔离（Windows 强制完整性 `NO_READ_UP`；Linux bubblewrap `--ro-bind /dev/null` 遮蔽）、资源限额（内存/CPU/进程数）、进程树终止、网络（Windows 代理拦截 + 提权 WFP 断网；Linux `--unshare-net` 空 netns）与高危命令拦截。这些条目的**唯一权威清单是 `popper experiment isolation` 的输出**（逐项带 `implemented` 布尔与前提说明，并标出当前选中的后端），本文不再另立一套口径；其中平台相关条目的**措辞由后端自己提供**（`capability_notes()`），避免在 Linux 上打印只有 Windows 才成立的机制描述。整树终止、资源限额与保留集禁读取决于对应内核机制是否可用，不是无条件承诺。

- 容器隔离不列入本地必做项——它解决的是"不可信第三方代码"威胁，该威胁在 BYOK 云算力 / 第三方仓库复现场景才成立；跨平台一致性留给未来 macOS 沙箱后端或容器。注意当前沙箱后端已登记 Windows 低完整性（`win_lowil`）与 Linux bubblewrap（`linux_bwrap`）：Windows 上 `--sandbox` 走 Low IL + Job Object；Linux 上 `--sandbox` 走 mount namespace 屏蔽 + `--unshare-net` + POSIX rlimit，且**可用性由实跑一次真实形状的沙箱探活得出**（`bwrap --version` 不够：非特权用户命名空间被 AppArmor 拒绝时它仍返回 0），探活失败即显式报错并给出修复指引（含 `--trusted-local` 可行路径）。`.github/workflows/ci.yml` 的 linux job 是硬门禁：显式装 bubblewrap、必要时为 `/usr/bin/bwrap` 开 AppArmor `userns` 例外、跑探活、并以 `POPPER_REQUIRE_SANDBOX=1` 使“后端不可用”从静默 skip 变红。macOS seatbelt 尚未实现（见 §2.2 后续演进第 1 条）。
- 引入 LangGraph 后复用状态契约，明确副作用幂等键、恢复语义和事件所有权，避免第二套状态源：编排层的**执行权威只有一处**，即 LangGraph checkpointer（`<run_dir>/graph.sqlite`）——它保存已执行超步、挂起任务与恢复点；`campaign.json` 降级为面向人与工作台的**派生投影**，不被读回决定"执行什么"或"从哪里恢复"。步骤的 `needs` 表达真实依赖：无前置的步骤从 `START` 并发起跑，每条依赖建一条真边，并发的扇入节点在节点内自检"全部前置已完成"作为屏障（LangGraph 默认任一父完成即触发）。恢复语义：checkpoint 仍有挂起任务则从挂起点续跑（已完成分支不重放），否则视为新一轮从 `START` 重放全图，靠节点自身幂等保证不重复副作用。
- LangGraph 与 `langgraph-checkpoint-sqlite` 是**可选依赖**（`pip install -e .[orchestration]`）。内核（实验协议、评估器、沙箱、审计）不依赖它们；缺依赖只影响 `campaign` 编排入口，其它路径照常可用。
- UI 后续可迁移 React，但先保留融合原型的信息架构和视觉语言；不为套框架重做当前实验契约。

## 3. 实验协议与数据模型

### 3.1 experiment.json

必需字段：`name / objective / entrypoint / code_files / train / dev / test / baseline / candidates / metric / seeds / budget / timeout_seconds / min_improvement`。可选 `provenance_files` 把数据来源说明等审计资料纳入输入指纹。

当前域包与协议约束：

- 注册期校验：一个域包恰好一个主指标、入口四字段齐全、任务形状必须在已实现集合内、调用契约必须是静态合法的 `Invocation`（占位符、路径安全、保留路径）。不合规在注册期立即失败，不会静默落到其它形状的语义。
- `aligned_prediction` 的数据行为 `id/x/y`（回归）或 `id/features/label`（分类），x/y 为有限数值，features 为等长有限数值列表，label 为整数（二分类 0/1；多分类非负整数）；`staged_artifacts` 的数据行为 `id` + 域包声明的工作负载字段。
- 训练/开发/测试 id 不交叉；内容完全相同的记录不跨划分。该检查不能发现全部语义泄漏，也不判断分布是否合理。
- 改善量按方向统一为正数代表更好，阈值采用绝对差。
- 配置、种子去重；有限数值检查；项目文件只允许根目录内相对路径。
- 候选尝试预算不包含基线；失败/中断同样计入预算；基线至多尝试两次。
- 完成的相同配置运行可以复用已登记结果；失败运行不能伪装成成功缓存。

### 3.2 执行适配器与域包

接入单元是**域包**（Domain Pack = 任务形状 + 数据契约 + 指标集 + 切分策略 + 重复单位），实现于 `popper/domains/`，导入即注册。调用契约（CLI 参数名、输入制品落位名、输出制品牌名）由域包声明，核心流程只按角色取路径，不内嵌某一种形状的字面量。已注册的评估契约如下（该列表由 `tests/test_doc_consistency.py` 与本行标记断言一致）：

<!-- ci-check: evaluators=mse-v1,binary-accuracy-v1,mae-v1,binary-f1-v1,multiclass-macro-f1-v1,algorithm-throughput-v1,convergence-order-v1,treatment-effect-v1 -->

- `aligned_prediction`（逐样本预测）：`mse-v1` / `binary-accuracy-v1` / `mae-v1` / `binary-f1-v1` / `multiclass-macro-f1-v1`。候选收到训练集、待预测输入、配置、种子；训练文件含标签，开发/最终数据传给候选程序时只含特征与 id。输出仅接受 `[{id, prediction}]`，拒绝自报 metric、重复 id、缺失预测、NaN/Infinity 等；控制器按 id 对齐评分，不能按数组位置猜测匹配。
- `staged_artifacts`（一次执行产出声明式制品）：`algorithm-throughput-v1` / `convergence-order-v1` / `treatment-effect-v1`。候选收到工作负载（或问题实例/队列）与配置、重复单位取值，输出一份只含**原始测量**的 JSON；指标由域包从测量派生，候选自报指标会被拒绝。测量字段可以是单个正数、**正数值序列**（`convergence-order-v1` 要求候选复述声明的细化表并逐网格报告误差序列，阶数由域包按 log(误差) 对 log(步数) 的最小二乘斜率取负拟合，误差未随加密严格下降即失败），或允许任意符号的标量与 0/1 标志（`treatment-effect-v1` 的 ATE 估计、处理标志）。三个领域的调用契约（参数名、输入落位名、制品牌名）都只由各自域包声明，核心流程不含形状字面量。
- 重复单位由域包声明，取值属受控词汇表：`train_seed`（逐样本领域）/ `independent_run`（吞吐、收敛阶）/ `analysis_unit`（处理效应）。前两者的重复取值来自 experiment.json 的 `seeds`，bootstrap 只反映训练或重复随机性，claim 恒为 `statistical_claim: false` 的描述性结论。`analysis_unit` 域包通过 `unit_values(rows)` 从每个数据划分导出单元（区块 id），experiment.json 不写 `seeds`，改为预注册 `significance_ratio`（方向判据 1−α）与 `min_units_for_significance`；对区块配对 bootstrap 满足预注册判据时 claim 才允许 `statistical_claim: true`，且该统计判据是 `supports_threshold` 的必要条件。
- `treatment-effect-v1` 同时落地非随机切分：区块必须**整块**分配到 train/dev/test、跨划分不重叠，且区块 id 按 train < dev < test 严格排序（冻结的确定性分配，由 `validate_splits` 强制执行）；每个区块必须处理组/对照组兼有。控制器按区块计分（`|ATE 估计 − 区块真实平均处理效应|`），真实个体效应 `tau` 字段在写入候选输入前剥离。
- holdout（一次性最终测试）有两条路径：
  - **控制器内路径**（`Experiment.evaluate(..., "test", ...)` / `_evaluate_via_worker(..., "test", ...)`）：同时支持 `aligned_prediction` 与 `staged_artifacts` 两种形状。test split 在 `evaluate` 入口检查 `phase=confirming`、`_require_holdout_seal` 与候选白名单后，按相同的 per-unit 执行 + 配对统计管线产出 `mean/std/per_seed`。staged 形状的 `score` 忽略 `unit` 参数（候选一次执行产出整批测量，由域包从制品派生指标），aligned 形状的 `score` 用 `unit` 定位单元内真值——两者共用同一条 holdout 路径，无需特殊分支。
  - **外部确认服务路径**（`popper/research/confirmation_runner.py`，第三方 process 消费测试集并签名回执）：仅支持 `aligned_prediction`，其它形状在 `require_aligned_prediction` 立即失败（在落盘任何 job 之前）。差异原因：外部确认服务固定按逐样本契约验证 features × predictions，staged 形状的「候选一次产出整批测量」契约不在其校验范围内。

正式结果包含：schema_version、run_id、split、config、metric、mean、std、per_seed、n_seeds、input_hashes、evaluator_id、evaluator_hash、environment、trust、elapsed_seconds。`per_seed`/`n_seeds` 是重复单位取值点集的存档字段名：训练种子域包其取值为种子，分析单元域包其取值为区块等单元 id（由域包 `unit_values` 导出）。

其中 input_hashes 绑定完整协议、注册代码及数据；`evaluator_id=mse-v1` 指向版本化评估契约，evaluator_hash 绑定该契约的定义。UI 或存储实现变化不会使旧实验失效；评估语义变化必须发布新 ID。environment 记录 Python 版本、解释器路径和平台，不宣称是完整依赖锁。外部依赖与 GPU 锁定属于下一阶段。

## 4. 状态机与最终测试

`searching → frozen → confirming → completed | confirmation_failed`。

- searching：只依据开发集提出/选择候选；结果不足时允许人工停止。
- frozen：基于开发集选择一个候选，冻结协议、输入与代码；停止继续搜索。
- confirming：先用事务登记 `test_consumed`，再执行基线和冻结候选的最终测试。
- completed：记录证据与描述性阈值结论；不能继续搜索或再次 confirm。
- confirmation_failed：即使执行失败，测试消费也不撤销；不静默重试。

最终测试结果不得回流同一次搜索。要继续研究，建立新实验并安排新的独立确认数据；复制项目或删除 .popper 不能使已经看过的测试集重新变得独立。当前本地工具不能阻止项目所有者绕过协议，这属于明确的信任边界。

恢复必须在原执行进程已经停止后显式运行 recover。已完成运行不重复执行；中断候选保留预算消耗；中断的最终测试进入失败终态。

### 4.1 通用论文复现任务

无法用固定 train/dev/test 表达的论文实验使用 `ReproductionTask`。任务根目录的 `reproduction.json` 必须登记论文 claim 记录、执行前协议、领域执行器、离线核验器、必需产物和超时。初始化冻结清单及四类输入的哈希；运行器只能执行一次，完成后记录 stdout/stderr、耗时和所有必需产物哈希；核验器必须从保存证据重算结果并输出单个 `status=verified` JSON 对象。

状态为 `registered → executed → verified`，执行或核验失败分别进入失败终态。读取状态会再次校验冻结输入和已登记产物。当前执行器与核验器仍属于可信本地代码，因此二者都要求显式 `--trusted-local`；领域核验逻辑是否充分仍由具体任务协议负责。

注册前的 `inspect` 是语义门禁。`paper.json` 必须记录题名、作者、年份、DOI、落地页，以及 claim 的文本、指标名称/方向/单位、报告值和证据位置；证据状态区分直接支持、间接支持和未核验。`protocol.json` 必须引用相同 claim id、指标和值，明确执行前冻结、容差、官方数据地址与预期 SHA-256。检查器发现两者不一致时拒绝注册；近似方法会作为 warning 保留到任务状态，防止报告升级为完全复现。

## 5. 创新点与假设树集成

Popper 是开源科研组件的统一集成宿主。第一条真实组件链已经接通：ResearchStudio-Idea 负责创新点工作流导航和候选产物，scientific-agent-skills 的 Arbor 负责持久化假设树、证据回写、洞见传播、剪枝与 merge gate；Popper 负责组件指纹、运行目录、结构化适配、跨组件溯源和自身的一次性最终测试约束。

当前可执行集成包括：

- `idea-next-v1` 调用 ResearchStudio-Idea 的真实 `run.py next`，把 `STATE / STEP / TYPE / PROMPT / RUN` 等导航契约解析为结构化 JSON，同时保留原始 stdout/stderr。
- `arbor-tree-v1` 调用真实 `tree.py`，开放 init、observe、status、validate、add-node、set-evidence、propagate、prune、merge 和 cycle，并把 tree/run 文件投影为 nodes、frontier、evidence、best candidate 等结构。
- `idea-to-arbor-v1` 按 `phase3_revise/final_candidate.json → phase2_coherence/refined_candidate.json → phase2_generate/phase2_generate_output.json` 的优先级选择 canonical candidate，以 `title + falsification_prediction` 建立 Arbor 节点，并保存候选相对路径和 SHA-256；相同候选重复桥接不会产生重复节点。
- `paper-search-v1` 通过隔离 worker（`popper.vendor_worker`）调用 ResearchStudio 的结构化 Python API 及其去重、排序实现，保存分来源原始回执、错误、查询指纹和时间。worker 以**转发**方式调用供应方 worker 函数并自行持有每来源 wall-clock deadline，不替换供应方模块的任何属性；该路径在非沙箱下执行供应方代码，因此 `paper-search` 与 `scoop-run` 都要求显式 `--trusted-local`。
- `scoop-check-v1` 由 Popper 按供应方七步协议编排。摘要初筛与全文核验分开保存；全文不足时结果只能是 `provisional`。`scoop-to-arbor-v1` 默认只接受 `completed`，并绑定检索与全文证据哈希。
- `arbor-popper-dev-v1` 把 Arbor node 映射到 `experiment.json` 的预注册候选索引，复用 Popper 的 baseline/dev 执行和控制器评分，将分数、方向统一 delta 与运行 ID 回写 Arbor。接口不接受 test split；最终确认仍只能经过 Popper freeze/confirm。
- `arbor-dispatch-v1` 使用 Idea、Scoop 摘要与候选白名单做受限语义映射。模型只能选择已有索引或明确返回不可实现；映射结果持久化并按输入指纹复用，不能借模型响应注入新配置。

Idea Spark 的完整流程仍包含 LLM 子任务、论文检索和碰撞审计。当前适配器真实驱动其导航器与本地产物契约，但尚未替 Popper 提供模型执行器和外部检索凭据；这些能力不能因为入口已接通就标记为全自动完成。

候选卡必含：最近邻工作、重合与差异、可证伪预测、最小区分实验、预计成本、证据来源及未知项。模型分级只能是建议，不能使用“重大创新已验证”等措辞。

检索输出包含源、查询、时间范围、原始回执、全文可达性和覆盖限制；不用“穷尽”作为默认承诺。引用存在性、元数据匹配、正文支持关系分别记录。未索引/不可达进入未验证状态，不等同于幻觉。

研究失败知识记录实现是否正确、预算是否足够、适用条件和后续可重试原因；不得把每个负 delta 永久标成此路不通。

## 7. 复用开源项目的原则

本工作区外层文件夹是 Popper 的开源组件源。Popper 不复制这些仓库的源码，而是通过受限适配器调用已登记入口；这仍属于真实运行时集成。`integrations/vendors.json` 登记来源路径、许可证、入口、SKILL 文件、能力和逐文件 SHA-256。当前外层目录来自压缩包且没有 Git 元数据，因此用文件指纹固定实际输入，不能虚构 commit。

- scientific-agent-skills 的 Arbor 已接入持久化假设树。其 worktree 不是恶意代码安全边界；原生 held-out merge gate 也不能绕过 Popper 的“冻结后一次最终确认”。
- ResearchStudio-Idea 的 `idea_spark` 导航器、`paper_search` Python API 和 `scoop_check` 协议已接入，并已实现带文献证据的 candidate 到 Arbor 节点桥接。Scoop Check 没有供应方可执行后端，因此明确由 Popper 编排，不能称为直接调用 Scoop API。
- nature-ref-verifier 的当前检查目录是 SKILL/agents/references 结构，不能假定存在可直接调用的字段核验服务。
- AI-Research-SKILLs 的 autoresearch 已作为 protocol 接入，Popper 可从真实 Arbor/实验状态生成 research log、findings 和结构化 snapshot；具体训练框架技能仍按项目需求逐项登记。academic-research-skills 的许可与内容边界在实际引入前按文件核实。
- AI-Research-SKILLs 的 `ml-training-recipes` 已作为首个工程指导 protocol 接入。`code-proposal-v1` 只读取已登记代码，以完整替换形式生成哈希绑定 diff，并执行路径、大小和 Python 编译门禁；应用补丁和实验注册仍是后续独立阶段。
- `code-variant-v1` 在明确审核标志后重新校验结构化 edits 与 unified diff，把原始/补丁代码物化为隔离实验。两者使用相同数据、配置、种子和控制器指标，原工作项目不被修改；派生实验 lineage 绑定 proposal 与源实验输入哈希。
- research-agent-v2/skills 当前是规划性技能集合；其中部分共享脚本/Schema 仍只有 README，不能计为完成的可执行能力。

每接入一个组件都必须固定许可证和实际文件指纹，限制输入/输出路径，保留原始回执，提供结构化状态，并覆盖正常、重复调用和越界/失败路径。供应方源码变化后，指纹检查先失败，再经过复核更新登记，不能静默漂移。

## 8. 安全、隐私与预算

当前可信本地模式必须显式 --trusted-local；--sandbox 启用 OS 原生隔离：Windows 上为低完整性写作用域 + 低权限进程（Low IL 令牌锁定）+ HTTP 代理拦截 + Python 层命令拦截 + Job Object 资源限额，提权环境下另启用 WFP 内核级断网；Linux 上为 bubblewrap 命名空间（`--unshare-all` + 宿主根只读 + 仅运行工作区 `--bind` 可写 + 空 netns 断网 + POSIX rlimit + `sitecustomize` 命令拦截）。`--trusted-local` 与 `--sandbox` 互斥。环境传递采用少量系统变量白名单，但它不能阻止本地脚本读取其他文件、联网或创建子进程。超时或失败时经作业对象/进程组（Linux 上经 namespace init 与 killpg）终止整棵进程树，可选 RLIMIT 限制内存与 CPU；除保留集标签外的文件读作用域仍未实现，Windows 非提权环境下的内核级断网也未实现（Linux 上由空 netns 提供），Linux 的 RLIMIT_NPROC 只能按真实 UID 给天花板而不是按作业精确计数，因此当前版本不执行未知来源的科研代码。

生产执行隔离验收（OS 原生沙箱策略，不依赖容器）：文件读写作用域（仅工作区可写、根目录只读）、训练进程无法读取最终标签、默认网络隔离、低权限进程、进程树终止、CPU/GPU/内存/磁盘限制、高危命令拦截与越界审批。命令白名单不能替代这些隔离。

BYOK 用户主动选择接口后，目标、候选配置和开发集指标会发送给其 provider。key 只从 POPPER_API_KEY 获取，不进入事件；禁远程明文 HTTP 与自动重定向。provider 数据政策由用户所选服务决定，不承诺云服务不训练。

当前执行预算为候选次数及每种子超时。模型请求限制响应大小和最大输出 token，但尚未实现精确账单估算、总输入 token 配额或 GPU 成本控制。未提供的能力不列作硬 SLO。

## 9. 验收

### 9.1 M0 工程验收

- 合成回归与真实公开二分类项目完成基线、至少一个候选、冻结、最终确认及可下钻证据。
- 注入重复样本/id、错误指标、自报 metric、无效预测、代码修改、证据修改，必须失败且不生成支持性 claim。
- 冻结后不能搜索，确认后不能再次测试；测试执行失败/中断也不能撤销消费。
- 完成运行可恢复复用，失败/中断候选仍计预算；离线重算不调用子进程或模型。
- 本地工作台读取同一 SQLite 状态，操作接口拒绝未授权/跨源请求，无伪造实验数字。

### 9.2 首个真实研究试点验收

采用同算力/模型预算的比较：人工现有流程、简单预注册候选搜索、反馈驱动 Agent。分别报告总尝试、有效完成、独立确认后的有效改善、错误建议、人工纠错时间、预算消耗。

不以“闭环不差于单次”作为唯一成功标准，不以回放一致证明有科研价值。先收集真实任务与研究者反馈，再登记可检验的继续/调整阈值，不能在看到结果后调整门槛。

统计确认需预先定义实验单位、效应量、CI、最小有用效应、重采样与多重比较规则。固定 3 个种子并不自动足够；未做统计检验时明确只给描述性结果。

### 9.3 后续引用与稿件审计

同时测召回、精确率、每稿误报数和人工复核时间。复现失败原因区分环境/数据缺失、源项目问题、工具错误与真实不一致。导入/审计允许缺失证据进入缺口报告；发布门禁才决定是否放行。

### 9.4 多领域接入待验证清单

本小节只回答一个问题：**「域包抽象能撑住多少种任务形状」验证到哪一步了**。它是广度边界清单，不是能力承诺。

| 试点领域 | 样例 | 暴露的形状缺口 | 状态 |
|---|---|---|---|
| 数值计算（ODE/PDE 收敛阶） | `examples/ode-convergence` | 非逐样本、多标量、需候选复述声明的细化表 | 接入完成；跑在合成问题实例上 |
| 系统（算法吞吐/延迟） | `examples/throughput-sort` | 重复单位 ≠ 训练种子、一次执行产出整批测量 | 接入完成；跑在合成工作负载上 |
| 计量/因果（处理效应） | `examples/treatment-effect` | `analysis_unit` 参与统计判据、非随机整块切分 | 接入完成；跑在带真值的合成队列上 |

**共同标准与它的真实代价**：三者的调用契约都只由各自域包声明，核心流程不含形状字面量；新增域包固定为「1 个模块 + 1 行导入」（见 `popper/domains/__init__.py`）。但第三个试点**确实要求改过 `popper/core.py`**：计分与统计管线被一次性泛化为按任意重复单位配对（`score(..., unit=...)`、`repeat_values`、按单元循环的 `evaluate`、单元层 claim 统计）。该泛化属「隐式约定被显式化」而非新增能力，之后再加域包不应再动 core——若还需改动，按抽象设计错误回炉。

**仍未验证（不得计入已完成）**：
- 一个用户自有、可运行、可承担算力费用的真实 ML 项目走完整闭环（即 §9.2 的同预算三臂比较）。三个现有试点的真值都是人造的，因此不能据此声称科研有效性。
- 非机器学习子领域（文本、图、多模态、纯数值仿真以外的实验科学）的接入成本与形状覆盖。
- `staged_artifacts` 形状走外部确认服务：该路径目前只支持 `aligned_prediction`（见 §3.2），第三方签名回执覆盖不到整批测量契约。
- 训练型/GPU 型任务的资源限额与长周期中断恢复（当前限额只有内存、CPU 时间、进程数）。
- 适用边界类任务的中性切片证据：36-cell 盲测里该格是四种任务条件里最弱的一格（具体命中数由 `ci-check` 标记锁定，只写在 `docs/实施记录.md` 的 2026-09-14 条目里，本文不重复数字以免出现无门禁的副本），需在冻结前登记多个中性切片规则才能改善。

## 10. 交付顺序

1. **M0a 工程底座（已完成）**：协议、MSE/accuracy 控制器计分、CLI、可信本地执行、状态机、证据重算、真实公开二分类示例、论文 claim 复现和本地工作台。物化层稿件渲染支持 `md` / `tex` / `docx` / `pdf` 四类模板（后两者为真实二进制渲染：PDF 自动探测并内嵌系统中文字体、以字形子集方式嵌入避免体积膨胀，中文与西文均可显示、可抽取，均强制带 AI 使用披露声明）。
2. **M0b 首条组件链（已完成基础接入）**：固定 ResearchStudio-Idea 与 Arbor 的许可证和文件指纹；接入真实入口、结构化状态和 Idea→Arbor 桥接。
3. **M1 组件链闭环（基础链路已完成）**：ResearchStudio `paper_search` / `scoop_check` 已让候选携带检索与全文证据进入 Arbor；Arbor node 已能调用 Popper 开发集执行器并回写控制器证据，同时保持最终测试一次性消费。
4. **M2 真实研究任务与隔离**：选择用户正在研究的 ML 项目，复跑基线并运行 Idea→Arbor→实验→证据闭环；加入 OS 沙箱策略（文件作用域/断网/命令拦截/越界审批）、代码版本、依赖锁和有效性对照。
5. **M3 扩展**：根据试点需求加入更丰富 UI、LangGraph、更多任务与稿件能力。

工期不再把研究不确定性压成 33–37 周确定承诺；每个阶段先证明出口条件，再估下一阶段。当前优先级是实际完成一个可信、可解释的实验任务。
